AI 블로그 작성 자동화 봇
이미지와 사용자 입력을 기반으로 AI가 블로그 초안을 생성하고, 생성된 글과 이미지를 네이버 블로그 편집기에 자동 배치하는 Windows 데스크톱 애플리케이션입니다.

단순한 글 생성기를 넘어 초안 생성 → 결과 분석 → 브라우저 편집기 입력 → 사용자 검토로 이어지는 반복 작업을 하나의 워크플로우로 연결했습니다. 최종 게시 전에는 사용자가 결과를 직접 확인하고 수정할 수 있도록 구성했습니다.

프로젝트 배경
블로그 글을 작성할 때는 다음과 같은 반복 작업이 필요합니다.

첨부할 사진을 확인하고 글의 순서를 구성

사진과 장소 정보에 맞춰 초안 작성

작성된 글을 문단별로 복사하여 편집기에 입력

알맞은 위치에 사진을 한 장씩 첨부

GIF처럼 처리 시간이 긴 파일을 별도로 확인

이 프로젝트는 이러한 과정을 자동화하여 사용자는 입력 정보와 결과 검토에 집중할 수 있도록 만드는 것을 목표로 개발했습니다.

주요 기능
이미지 폴더 및 글 작성 정보 선택

Codex CLI를 이용한 블로그 초안 생성

style_profile.json 기반 문체와 작성 규칙 적용

생성된 마크다운 문서의 텍스트·사진 마커 분석

Playwright를 이용한 네이버 블로그 편집기 자동 입력

사진 첨부 방식 팝업을 방지하기 위한 이미지 단건 순차 업로드

GIF 업로드 시 다음 작업 전 대기시간 자동 조정

별도 작업 스레드를 이용한 GUI 응답성 유지

작업 진행 상황과 print() 출력을 GUI 작업 로그에 표시

오류 발생 시 스택 트레이스와 사용자용 오류 메시지 제공

PyInstaller를 이용한 Windows 실행 파일 배포

주요 기술 문제와 해결

1. 개발 환경과 EXE 환경의 리소스 경로 차이
   개발 환경에서는 프로젝트 최상위 폴더의 img, output, style_profile.json을 사용하지만, PyInstaller로 빌드한 프로그램은 실행 위치가 달라질 수 있습니다.

다음 규칙으로 공통 경로를 결정하도록 분리했습니다.

개발 환경: 상위 디렉터리를 탐색하여 pyproject.toml이 있는 프로젝트 루트 사용

배포 환경: 프로젝트 파일이 없으면 실행한 EXE가 있는 디렉터리 사용

경로 결정 책임을 paths.py로 분리하여 GUI와 워크플로우가 동일한 기준을 사용하도록 구성했습니다.

2. 작업 중 GUI가 멈추는 문제
   AI 초안 생성과 브라우저 자동화는 시간이 걸리는 작업이므로 Tkinter 메인 스레드에서 실행하면 화면이 멈춥니다.

실제 작업은 별도 Thread에서 실행

작업 결과는 스레드 안전한 Queue에 이벤트로 전달

GUI 메인 스레드가 이벤트를 읽어 진행 상태와 로그 갱신

이를 통해 글 생성 중에도 GUI가 응답하도록 구현했습니다.

3. 콘솔 없는 EXE에서 진행 상황 확인
   콘솔 창을 숨긴 EXE에서는 기존 print() 내용을 확인할 수 없었습니다. 작업 스레드의 표준 출력과 오류 출력을 이벤트 큐로 전달하여 GUI의 작업 로그 영역에서 진행 상황을 확인할 수 있도록 개선했습니다.

4. 이미지 연속 업로드 안정화
   여러 이미지를 한 번에 전달하면 네이버 편집기에서 사진 첨부 방식 선택 팝업이 나타날 수 있어 이미지를 한 장씩 첨부하도록 구현했습니다.

이미지마다 새로운 파일 입력 요소 탐색

일반 이미지 업로드 후 다음 작업까지 짧은 대기

GIF 업로드 후에는 처리 시간을 고려해 10초 대기

파일 종류에 따라 대기시간을 다르게 적용하여 불필요한 지연을 줄이면서 업로드 안정성을 유지했습니다.

5. PowerShell 창 노출 문제
   GUI에서 하위 프로세스를 실행할 때 새로운 PowerShell 창이 표시되는 문제가 있었습니다. Windows 환경에서는 CREATE_NO_WINDOW 옵션을 적용하여 글 생성은 백그라운드에서 계속 진행하고 별도의 콘솔 창은 표시되지 않도록 처리했습니다.

보안 및 사용 시 주의사항
Codex 인증 정보와 브라우저 로그인 정보는 프로젝트에 포함하지 않습니다.

API 키, 인증 파일, 개인 이미지 및 생성 결과물을 Git에 커밋하지 않습니다.

프로그램이 입력한 결과는 게시 전에 반드시 사용자가 검토합니다.

웹사이트의 화면 구조가 변경되면 Playwright 선택자 수정이 필요할 수 있습니다.

서비스 운영정책과 관련 법규를 준수하는 범위에서 사용해야 합니다.
